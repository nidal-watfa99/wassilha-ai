# البنية المعمارية (ARCHITECTURE)

## نظرة عامة

```
┌──────────────────────────── المتصفح ───────────────────────────┐
│  واجهة React 18 (Vite)                                          │
│  ├─ AppContext: الجلسة، اللغة (ar/en/es)، التنبيهات             │
│  ├─ RealtimeContext: قناة WebSocket /ws (إعادة اتصال تلقائية)    │
│  └─ CallContext: اتصال WebRTC + الإشارات عبر WebSocket          │
└───────────────┬──────────────────────────┬────────────────────┘
        REST‏ /api/*‏ (fetch + ترويسة CSRF)   WS‏ /ws (مصادقة كوكي)
┌───────────────┴──────────────────────────┴──────────────────────┐
│  خادم FastAPI (backend/server.py)                               │
│  ├─ برمجيات وسيطة: CSRF (ترويسة X-Requested-With)، CORS،        │
│  │   تقييد معدل الطلبات (في الذاكرة — مناسبة لنشر أحادي العملية) │
│  ├─ المسارات: auth, contacts, messaging, tasks, documents,      │
│  │            ai, commerce, insights, meta, ws                  │
│  ├─ الخدمات: security (Argon2/JWT/الإبطال)، files (MIME +       │
│  │   البصمة السحرية)، realtime (إدارة الاتصالات)، ai            │
│  └─ SQLAlchemy 2.0 → SQLite (تطوير) أو أي قاعدة SQL عبر DATABASE_URL │
└─────────────────────────────────────────────────────────────────┘
```

## طبقات الخادم

- **server.py** — بناء التطبيق والاهتمامات المشتركة:
  - CSRF: كل طلب يغيّر الحالة يجب أن يحمل ترويسة `X-Requested-With: XMLHttpRequest` (استثناءات: تسجيل/دخول/خروج/الصحة — وهي محمية بتقييد المعدل). هذه آلية «ترويسة مخصصة يجب معرفتها مسبقاً» وليست نظام Double-Submit — ذكرٌ دقيق.
  - تقديم الواجهة: عند وجود `backend/static/` يقدّم الخادم الواجهة المبنية على `/` (الجذر مشمول) مع fallback مفحوص ضد اجتياز المسار؛ مسارات `/api/*` تعيد JSON دائماً.
  - حارس الإنتاج: يرفض الإقلاع مع `WASSILHA_ENV=production` بدون `JWT_SECRET`.
- **models/db.py** — الجداول: User, Contact, Conversation, ConversationMember, Message (قيد فريد `conversation_id + client_key` لمنع تكرار الإرسال)، StoredFile, Task, Event, Document, Product, Payment, AIConversation, AIMessage, RevokedToken.
- **services/security.py** — تجزئة كلمات المرور بـ Argon2؛ رموز JWT تحتوي `jti` تُسجَّل في جدول إبطال عند الخروج (تبقى فعّالة بعد إعادة تشغيل الخادم)؛ تقييد معدل في الذاكرة (قاموس لكل مفتاح).
- **services/realtime.py** — سجل اتصالات WebSocket لكل مستخدم، للرسائل الحية وإشارات المكالمات.
- **services/files.py** — قائمة سماح للامتدادات وأنواع MIME مع التحقق من البصمة السحرية للملف؛ حدود الحجم من الإعدادات.
- **services/ai.py** — محول متوافق مع OpenAI. يرفع `AINotConfigured` → ‏HTTP 503 برمز واضح؛ الواجهة تعرض حالة «غير مهيأ» صراحة بدل تزييف الردود.
- **routes/ws.py** — فحص الأصل، مصادقة الكوكي، سجل المكالمات النشطة؛ يتحقق أن `call-answer`/`call-ice`/`call-end` تأتي من أطراف المكالمة فعلاً، وأن طرفي `call-offer` يشتركان في المحادثة قبل تمثيل SDP عبر `incoming-call`.

## بنية الواجهة

- `pages/` — تسجيل الدخول، الرئيسية، جهات الاتصال، الرسائل، المهام، التقويم، المستندات، المساعد الذكي، الإحصاءات، المنتجات، الآلة الحاسبة، الإعدادات، حول.
- `context/CallContext.jsx` — دورة حياة WebRTC كاملة: getUserMedia، ‏RTCPeerConnection، تخزين مؤقت لمرشحي ICE، حالة البث البعيد، التنظيف الكامل.
- `services/api.js` — غلاف fetch (ترويسة CSRF تلقائية، معالجة 401) ورفع XHR مع تقدم.
- `i18n/` — قواميس ar/en/es؛ اتجاه `dir` يتبدل على مستوى المستند.
- `styles/design-system.css` — الرموز المستخرجة من الموقع المرجعي (انظر DESIGN_SYSTEM.md).

## تدفقات البيانات

- **إرسال رسالة**: ‏POST إلى `/api/conversations/{id}/messages` (عزل تكرار عبر `client_key`) → حفظ → بث عبر WS لكل الأعضاء → واجهة متفائلة مع إعادة محاولة عند الفشل. لا تُوسم الرسالة «مُرسَلة» إلا بعد قبول الخادم فعلياً.
- **المكالمة**: المتصل ينشئ العرض → `call-offer` عبر WS → الخادم يتحقق من المحادثة المشتركة → `incoming-call` إلى الطرف الآخر → الرد/ICE يُمثَّلان مع تحقق الأطراف → الوسائط تتدفق مباشرة بين الطرفين (STUN/TURN من `/api/config/webrtc` — تتطلب مصادقة).
- **محادثة الذكاء الاصطناعي**: POST إلى `/api/ai/chat` → المحول → المزود. غير مهيأ → ‏503 → حالة واجهة صريحة.

## قرارات الأمان

- جلسات بكوكيز HttpOnly + ترويسة CSRF؛ لا رموز في localStorage.
- كل نقطة نهاية تتحقق من الملكية على الخادم؛ فحوصات الواجهة تجميلية فقط.
- WebSocket: قائمة سماح للأصل + مصادقة الكوكي + تحقق من الأطراف لكل رسالة إشارة.
- كلمات المرور: Argon2id. الإبطال يبقى بعد إعادة التشغيل (مخزَّن في قاعدة البيانات).
